# テスト

サーバー(`api/`)と拡張機能(`extension/`)の**実コードを読み込んで**動かす検証です。
Redis(Upstash) はメモリ上で模倣します。外部への通信は行いません。

## 実行

```
node tests/run-all.mjs        # 全部まとめて
node tests/dup.mjs            # 個別（詳細な内訳が出ます）
```

## ブラウザが要るテスト（run-all には含めない）

`node tests/sitealert.mjs` … 巡回停止の警告帯。**先に `npm run dev` を起動しておくこと**（Playwrightで実画面を操作するため）。

`node tests/kazaiscrape.mjs` … 価格.comの家財（お荷物量）の抜き出し。**dev サーバーは不要**（Playwrightに実測どおりのHTMLを流し込んで確かめる）。

`node tests/leadlock-e2e.mjs` … リードの「対応中」印を、ブラウザ2つ（＝2人）で通しで確認する。**先に `npm run build` が必要**（dist を自前の簡易サーバーで配信する。dev サーバーと本番Redisは使わない）。

`node tests/tabs-e2e.mjs` … 追客（50件ずつ）・広告費（当月と先月＋選んだ月を追加）・見積書（50行ずつ）・上部の更新ボタン非表示を、本番並みの件数でブラウザから通しで確認する。広告費は全件で数えた値と一致するかまで見る。**先に `npm run build` が必要**。

## 各スイートの内容

| ファイル | 検証していること |
|---|---|
| `leadlock.mjs` | 同じリードに複数人が架電してしまうのを防ぐ仕組み。**同時に5人が開いても1人しか取れないか**、閉じたら戻るか、ブラウザが落ちても60秒で解放されるか |
| `perf.mjs` | リードを全件（8MB超）読まないようにした改修。**更新ボタンが直近50件だけで新着・他人の変更を反映できるか**（新着が消えない・重複しない、削除や51件以上の増加は全件で取り直す）、追客タブの50件ずつの読み込み（重複・取りこぼしなし）、広告費の月指定の読み込み、新着通知のポーリングが数KBのキーしか読まないか |
| `kazaimap.mjs` | 価格.comの家財名50品目が、**見積書の品目**と**リード詳細のカテゴリ**に正しく結び付くか。既存2サイトの語彙を壊していないか、**語彙表に重複が無いか**、家財を選ぶモーダルの作りも見る |
| `dup.mjs` | 重複リード取得時に**利用者のメモ・ステータスが保護されるか**、**重複が新規リードとして追加されないか**。実際のクローラーが送るペイロード形状を再現。20人×3サイト×5巡回の通し運用も含む |
| `audit.mjs` | 別リードのメモ・ステータスが混入しないか（顧客報告の不具合） |
| `fillonly.mjs` | 住所・要望・家財が「空欄なら補完／入力済みなら保護」になっているか |
| `bugcheck.mjs` | Luaの戻り値、バージョンキー未作成からの移行、成約の重複登録防止 |
| `bugcheck2.mjs` | 保存データ破損時に全件消失しないか、異常な入力でクラッシュしないか |
| `kvtest.mjs` | 同時書き込みでリードが取りこぼされないか |
| `exttest.mjs` | 拡張機能が送信失敗を正しく判定するか（500で諦めない） |
| `exttest3.mjs` | 再送が新着リードを塞がないか、無限に再送しないか |
| `zbafix.mjs` | ズバットの自動再ログインが**拒否(4xx)を正しく上限にカウントして止まるか**、生存確認が**空CSRFトークンでログイン切れを検知するか**。2026-09のパスワード変更事故の再発防止。完全ログアウト時もログインを試み、上限2回で止まることも確認 |

## 注意

**これらは実際の Upstash / 各査定サイトには接続していません。**
ロジックの検証であり、本番環境での動作確認は別途必要です。
