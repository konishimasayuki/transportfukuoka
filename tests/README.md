# テスト

サーバー(`api/`)と拡張機能(`extension/`)の**実コードを読み込んで**動かす検証です。
Redis(Upstash) はメモリ上で模倣します。外部への通信は行いません。

## 実行

```
node tests/run-all.mjs        # 全部まとめて
node tests/dup.mjs            # 個別（詳細な内訳が出ます）
```

## 各スイートの内容

| ファイル | 検証していること |
|---|---|
| `dup.mjs` | 重複リード取得時に**利用者のメモ・ステータスが保護されるか**、**重複が新規リードとして追加されないか**。実際のクローラーが送るペイロード形状を再現。20人×3サイト×5巡回の通し運用も含む |
| `audit.mjs` | 別リードのメモ・ステータスが混入しないか（顧客報告の不具合） |
| `fillonly.mjs` | 住所・要望・家財が「空欄なら補完／入力済みなら保護」になっているか |
| `bugcheck.mjs` | Luaの戻り値、バージョンキー未作成からの移行、成約の重複登録防止 |
| `bugcheck2.mjs` | 保存データ破損時に全件消失しないか、異常な入力でクラッシュしないか |
| `kvtest.mjs` | 同時書き込みでリードが取りこぼされないか |
| `exttest.mjs` | 拡張機能が送信失敗を正しく判定するか（500で諦めない） |
| `exttest3.mjs` | 再送が新着リードを塞がないか、無限に再送しないか |

## 注意

**これらは実際の Upstash / 各査定サイトには接続していません。**
ロジックの検証であり、本番環境での動作確認は別途必要です。
